## 1. Backup matrix

| Store | Method | Frequency | Target | RPO |
|---|---|---|---|---|
| PostgreSQL | **WAL-G**: continuous WAL archiving + nightly base backup | WAL: continuous; base: nightly | Off-site bucket (second location / second box in offline profile) | ≤ 5 min |
| MinIO media | Bucket versioning + scheduled `mc mirror` to backup site | hourly (backups bucket), daily (media) | Second site/box | ≤ 1 h backups, ≤ 24 h media |
| Valkey | **None — by design.** Nothing durable lives there ([valkey-keyspace.md](valkey-keyspace.md)) | — | — | — |
| NATS streams | Short-retention transit; truth is PG inbox → replayable | — | — | — |
| Cluster/config | Git (GitOps) + Terraform state backend | on change | — | 0 (declarative) |
| Secrets | SOPS-encrypted in Git; age keys escrowed offline (2 holders) | on change | — | — |

## 2. PostgreSQL PITR procedure (summary — full runbook in ops/runbooks/)

1. Provision replacement instance (CloudNativePG `Cluster` manifest from Git).
2. `wal-g backup-fetch` latest base → `wal-g wal-fetch` replay to target LSN/time.
3. Validate: row counts on `users`/`devices`; inbox partition sanity; sequence values ≥ max(seq) (**critical** — a rewound `conversations.seq` would violate ordering: verify `SELECT max(seq)` per active conversation against replayed WAL end).
4. Repoint PgBouncer; deployables reconnect (stateless); clients recover via outbox retry + resume replay.

## 3. What recovery means per data class

| Data | After PG restore to T-5min |
|---|---|
| Messages ACKed before T-5min | Already delivered or safely in inbox — intact |
| Messages accepted in the lost window | Client outboxes still hold them (no server ACK seen or ACK'd-but-lost) → **retry re-accepts; dedupe absorbs overlap.** End-user loss: none |
| Receipts in the window | Regenerated by clients on reconnect |
| Registrations in the window | User repeats OTP flow (10-min OTPs expired anyway) |
| Media in the window | `media_objects` row lost → upload session invalid → client re-uploads; orphan MinIO blob GC'd by lifecycle rule |

This table is why the relay model + client outbox makes a 5-minute RPO *feel* like zero to users.

## 4. Restore drills (non-negotiable)

- **Quarterly:** full PITR restore to a scratch namespace; automated validation suite runs against it; drill results logged in ops/runbooks/.
- **Quarterly (alternating):** region/site-loss game day — rebuild cluster from Git + backups only, measure against RTO ≤ 60 min.
- **Rule:** a backup that hasn't been restore-tested does not exist.
